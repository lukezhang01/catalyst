## Project board: GitHub Projects (Kanban)

**Maintainer:** [TODO: member responsible for board upkeep.]

**Why this tool:** GitHub Projects keeps planning close to the repository's issues and pull requests. A shared Kanban board makes ownership, progress, and blockers visible.

**Suggested columns:** Backlog → Ready → In progress → In review → Done.

- Create an issue for each meaningful task with an owner, acceptance criteria, and a target date or milestone.
- Move an item to Ready when its scope is clear; move it to In progress when work begins.
- Open a PR for repository changes, link the issue, and request a teammate's review. Use `Closes #<issue-number>` when merging the PR should close that issue.
- Move work to In review when ready for feedback, then Done when the operating agreement's completion criteria are met.
- Mark blocked items explicitly and explain the dependency in the issue. Review the board during the weekly check-in.
